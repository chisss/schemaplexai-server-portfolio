# Service 设计决策

## 桌面对话与执行记录（2026-11-21）

桌面会话使用稳定的原始 ID，Solo 记忆使用带租户前缀的 ID。读取历史或恢复中断的提交时，按登录租户、会话所有者和这两种会话 ID 查询执行记录。已有执行 ID 的消息按该执行 ID 查询，提交中的消息按请求 ID 恢复。

## Team 图执行线程（2026-11-21）

LangGraph 的父图和子图各自在虚拟线程执行。提交时捕获已认证调用方的租户和用户身份，每次执行图节点和路由时在该线程内绑定身份，并在退出时清理，供租户过滤、审计及下游成员任务使用。

## 执行活动流（2026-11-24）

执行步骤通过 SSE 发布 `ACTIVITY_STEP`，同一步骤的进度和终态共享一个 ID。持久化的步骤快照可从执行详情的同权限接口回放，最多读取最近 600 条。模型的流式回调只发送阶段说明。服务端按完整响应执行工具和验证终稿，每次模型派发仍消耗同一执行预算。

## Agent 模型请求与归档（2026-11-21）

候选模型发送前核对指令、历史、工具定义、媒体和输出余量。超出窗口时移除最旧完整轮次，能力不匹配时继续尝试链中其他候选。Team 仅向 Leader 交付原始附件引用，每次恢复按父执行重新校验。

桌面文件读取成功时，服务端为读取参数和实际结果生成指纹。发送模型请求前，内容完全相同的较早读取使用调用 ID 引用较新的完整结果。所有调用及回执仍完整归档，改过的文件和失败结果不会合并。

配置验收命令的桌面执行按历史工具回执压缩旧消息，保留当前任务原文和最近完成的工具交换。当累计执行额度无法容纳下一次请求时，模型路由记录 Token 预算边界，并沿用现有终态验收逻辑。

模型请求中的完整桌面工具交换可以引用同一用户轮次、同路径较新且有设备成功回执的完整写入。最近两组交换保留原样，写入原文在归档中保留。设备验收通过后如果只能生成降级结论，执行状态记录为 `completed_with_fallback`。

旧桌面写入及精确编辑可引用同一任务中之后的完整文件读取。服务端核对设备回执、路径和内容指纹。遇到中间写入、Shell 或无法确定顺序时保留原参数。带有唯一成功 Maven 回执的轮次允许同时包含关联完整的本机只读调用，供后续请求投影旧源码读取。

未知操作清除跨越该轮次的文件读取证明。未知操作之前已关联的成功写入和完整读取仍可用于该历史版本，模型同时保留后续观测到的文件版本。

发往模型的本机文件读取结果通过完整回执、调用参数和内容指纹核对后，使用单层 JSON 保留路径、可选行号和原文。工具消息继续携带调用身份和状态。失败、截断、旧回执或无法验证的结果沿用原有格式，设备回执及审计归档保留完整原文。

已通过结构校验的桌面 Maven 成功回执随模型请求发送退出码和测试汇总。通用历史遮蔽按该摘要计算长度，并保留其余回执的原有遮蔽策略。归档保存原始构建日志，以便独立核验。

经设备回执确认的成功构建，可在当前任务的后续读操作中将较早的完整源码回执替换为路径、范围和指纹。最近两个完整工具交换和被其他证据引用的正文保持可读。出现失败、写入、未知 Shell 或用户引导时恢复完整输入，审批恢复沿用原始证据路径。静默 Maven 只确认实际退出码，测试统计和最终验收继续由原有回执判定。

桌面 Shell 截断长输出时保留首尾。服务端为与设备调用关联的 Maven 失败回执提取退出码及编译错误，同时兼容未提供截断标志的旧版设备。历史压缩保留最近一次此类诊断。失败回执仍按原始状态参与交付验收。

需最终验收的桌面编码任务在实际写入后的连续只读轮出现重复指纹，或连续三轮读取尚未推进到修复或构建时，提示模型基于现有证据继续执行。验收预算提示使用最近一轮实耗估算，缺少当前有效回执时，余额不足五轮及三轮各提示一次。提示仅附于本轮系统指令，保留用户消息边界及工具去重范围。最终状态取决于实际验收回执。

模型返回空响应或拒绝单次请求的载荷时，当前请求仍可按候选链降级。认证、账户、限流和超时按租户及实际模型通道短期冷却，便于其他配置继续服务。

性能复验可显式设置 `SCHEMAPLEXAI_AGENT_MODEL_REQUEST_COMPONENTS_ENABLED=true`。服务端按请求跨度 ID 记录最终请求各部分的估算 Token。含工具历史的请求另记录助手正文的估计量，并按固定工具类别记录调用参数和回执的估计量。供应商实际用量仍由请求账本独立记录。开关默认关闭，记录只包含计数与分类。

任务上下文去重实验由 `SCHEMAPLEXAI_AGENT_MODEL_TASK_CONTEXT_PROJECTION_ENABLED` 控制，默认关闭。新建纯文本 Solo 执行仅在候选窗口仍保留同一条完整用户原文时省略系统提示中的重复任务段。Team 首次运行定义时，编排器核对归档的父任务原文，为符合条件的成员执行标记完整指令及成员身份。去重只发生在窗口中保留同一个成员消息、且内容与系统任务段逐字相同时。角色上下文和记忆仍按各自的段落注入，成员指令仍作为合成输入归档。模型窗口失去该消息后恢复系统段并重新计算预算。含最近会话的 Team 请求、附件、临时会话、恢复、成员重试和执行中引导使用完整系统任务段。开启前须用实际供应商用量和交付质效复测。

Agent 执行从 PostgreSQL 加载有界历史到执行内模型窗口。记忆压缩、旧工具结果遮蔽和请求规范化只修改模型视图。原始消息按执行追加，审批恢复按调用 ID 补齐轨迹。长期记忆只处理当前执行可归因的原文，写入与提取幂等标记使用同一事务。临时模式从保存的运行策略恢复，跳过用户与 Agent 长期记忆读写。

配置了最终验证命令的桌面任务仍按当前设备回执判定是否通过。模型在预算内提前提交终稿时，可获得一次补验提示。连续三轮只重复已确认的完整文件读取时，单次执行中附加一次推进提示。可能改变工作区的调用清除读取指纹。模型仍通过已绑定的入口执行工具，每笔调用接受原有审批和风险检查。

Solo 在轮次边界按顺序消费用户引导。待处理引导的状态变更和原文归档使用同一个 PostgreSQL 事务，提交后更新模型窗口。归档失败时保留待处理状态，恢复时可从归档重建已提交的引导。

质量任务的 `resultSummary.coverage` 记录检测器调用计数、评审配置解析结果及模型评审状态。历史任务仍可按原有字段读取。通用评审结果缺少模型调用证明时以未知状态展示。

手动偏离检测将同租户执行的原始任务作为独立的评审材料。关联的 Spec 仍参与交叉审查。历史任务未提供原始任务时，使用现有评审输入。

Solo 和 Team 父执行在发送完成通知前，从 PostgreSQL 单独读取本次执行的用户原文。显式记忆通过中英文规则提取，无需调用模型，后续新会话可立即读取。Team 成员的编排提示和工具输出不作为用户记忆来源。Agent 运行经验的模型提取继续异步执行。

自动生成 Agent 专属指令时，成功落库才保存生成输入和已写指令的 SHA-256。记忆文本、模板和模型生成配置相同则复用已有指令。人工维护的条目与生成后手工修改的内容保留。单实例合并同一 Agent 的并发生成，写入时校验读取时的条目更新时间。失败或空响应可在下一次执行完成后重试。

Agent 记忆正文使用 PostgreSQL `TEXT`。提取允许单条记忆达到 500 字符，整合结果也复用该列。完整交付环境通过数据库迁移升级旧库，保留历史正文、租户、Agent 和阶段。重复迁移时已升级列保持 `TEXT`。

服务端从已验证归属的桌面会话保存执行项目。恢复和 Team 成员继承该项目。同一会话移动到另一个项目后，模型只读当前项目的归档轮次。项目内显式记忆写入 USER_PROJECT，项目执行跳过共享 Agent 经验提取。

## MCP 传输兼容（2026-11-21）

`streamable_http` 使用 SDK HTTP 传输，`sse` 保持现有 Streamable HTTP 附属通道语义。旧版独立 GET/POST 服务须显式选用 `legacy_sse`，按服务器公布的同源地址发送 POST。兼容传输拒绝重定向，避免认证头离开配置的服务来源，提交失败的工具调用由上层按幂等契约决定是否重试。

## Agent 对话附件授权（2026-11-21）

Web 与 Desktop 的对话上传均登记现有 `sf_desktop_attachment`，并校验会话通道、租户、所有者、有效期和大小。Web 接口保留原有返回结构。上线前确认工作区附件表已创建，旧上传缺少所有者记录时需要重新上传。单轮附件总大小上限为 20 MiB，原生图片单张上限为 12 MiB，构建图文消息时检查实际 MIME。

## Agent 工具批次调度（2026-11-21）

同轮仅相邻的只读调用在有界批次内并发。后继批次及写工具等待上一批结束。单条执行或只读批次返回安全中断后，后续调用收到带原调用 ID 的跳过回执。线程池拒绝仅使相应未提交调用返回繁忙。已提交调用保留其 Future，开始执行前重新检查取消状态。

## 上下文解析范围（2026-11-21）

项目和任务层仅加载请求指定项目的资料。Agent 层先通过租户过滤的 Agent 查询确认归属，再根据启用的绑定加载本租户的 Agent 级上下文。缺少对应范围时，该层保持空白。绑定表通过父 Agent 获得租户边界。

## 企业 Desktop 设备通道（2026-11-19）

Shell 审批修订仅补充单条命令的白名单。STRICT、提权与结构检查优先，命令链各段须逐一匹配沙箱白名单。企业工具前置与后置审核以及桌面进程隔离仍在各自边界执行。

已接收的设备回执在工具消息归档中携带 Broker 生成的 `desktopCallId`，可按原生调用关联审批、执行和回传时间。模型工具调用 ID 继续用于消息配对，回执文本格式保持原样。

Agent 核心保持在 Server；显式 Desktop 目标经真实工具会话工厂进入设备执行器，原有安全 PRE/POST 和沙箱不变。JWT 身份约束设备与调用；Desktop 历史分页、详情、日志、控制和会话续接按执行 owner 隔离。执行前核验拒绝已取消或过期的旧确认；已开始动作不能远程回滚。单节点 Broker 为有界内存实现，120 秒超时，不支持重启恢复或跨节点领取。完整威胁模型与限制见 [Desktop 设备桥设计](src/main/java/com/schemaplexai/service/desktop/DESIGN.md)。

## Agent 框架依赖对齐（2026-11-19）

LangChain4j 核心与官方扩展由 `1.24.0` BOM 对齐，显式声明的扩展使用 `1.24.0-beta34`。Community MCP Server 的最新独立制品为 `1.23.0-beta33`，单设版本属性，避免引用尚未发布的版本；其传递核心依赖仍由主 BOM 统一管理。

LangGraph4j Core 与 PostgreSQL Saver 统一使用 Maven Central 最新可解析正式版 `1.9.9`；GitHub 的 `1.9.10` 发布尚无对应 Maven 制品。升级验证覆盖模型 HTTP 请求与工具调用解析，以及真实 PostgreSQL checkpoint 的暂停和恢复，保持现有 Java 21 与 Spring Boot 3 运行环境。

新版 Saver 将 checkpoint 状态从 JSONB 的 `binaryPayload` 包装改为 TEXT；升级时应用完整交付环境提供的 checkpoint 迁移，保留原始 Base64 和 `state_content_type`，不删除历史线程。脚本检查旧载荷结构，异常时事务回滚；重复执行不改变已迁移表。回归测试使用 1.8.13 生成的真实序列化载荷验证兼容性。

Milvus SDK 对齐官方集成要求的 `2.6.27`，避免继续强制使用 `2.4.3` 造成运行时缺少方法。`milvus.enabled=false` 时允许 RAG 工厂缺少 Milvus Bean，并直接跳过检索，保持非向量功能可启动。

## Team 执行恢复与调度（2026-11-21）

Team 启动和恢复的外层异常以稳定提示落库并发布，内部日志按执行 ID、阶段和异常类型关联。包含数据库错误的失败会直接进入失败终态。旧库扩大状态列后可写入超过 20 字符的兜底终态。

恢复输入在暂停时原子领取执行，同一暂停只有一份恢复任务进入编排池。运行中补充文本进入执行引导，在下一成员轮消费。结束、暂停和恢复失败由本次执行从 running 原子写入并发布对应事件。Checkpoint 释放失败单独记录，业务终态以已写入的执行状态为准。

停止 Team 父执行时，同一事务停止该租户、Agent 和父执行下的排队、运行或暂停成员。桌面任务额外匹配工作区执行所有者。新建成员在短事务中先锁定仍在运行的父执行，使新成员可以被随后执行的停止操作看到。取消事件在事务提交后发布。

Team 图使用独立有界编排池等待子执行，成员与 Solo 内核共用 Agent 执行池。恢复调度遭拒时撤回领取，暂停任务可再次恢复。

当桌面 Team 配置最终验收命令时，成员提示按本机 Shell 绑定说明交接职责，优先复用实际产物与工具结果。提供本机 Shell 的会话按模型侧工具名注入原样提交指令。根执行继续核验指定工作目录和成功退出码对应的设备回执。

桌面验收按实际退出码与输出判定无效输入检查，复用同一未变产物的有效回执。模型提示说明 Java 启动器会在标准错误附加隔离配置诊断。执行器继续保留原始标准错误和既有沙箱配置。

本机 Maven 回执含有源文件行号诊断时，执行循环在下一轮提示合并同一文件的修复，并复用已有源码。预算接近上限时，已有有效最终回执的任务优先交付已完成的工单，仍缺检查时为这些检查、最终命令及交付预留轮次。提示仅加入本轮模型请求。工具派发、企业审批、预算扣减和最终回执核验沿用原有流程。

领队读取桌面最终验收交接时，为验收负责人的结果预留 1,900 字符，总交接预算仍为 2,200 字符。有实际成功回执时，领队先按任务逐项核对交接，再处理缺少的验收证据。

桌面终稿按任务要求引用命令对象、输入、实际输出与退出码，分别交代早期 CLI 验收和最终构建。Team 用户要求角色分工时，领队汇总各角色真实产出。

已有有效最终验收时，Team 领队读取验收负责人当前执行归档中的设备回执。命令和工具调用关联一致，并且回执完整时，交接最多四项 HTTPS HEAD 的命令、实际状态行和回执编号。如果同一归档还保留最后的配置验收命令，则同时交接退出码、已有的 Maven 测试汇总和该命令之前的有限数量 Java 数值 CLI 验证。CLI 交接保留退出码和数字 stdout，应用 stderr 只记录是否有输出。领队按工单要求分别说明构建前检查和最终构建。

最终验收负责人也会收到紧邻上一位成功成员的相关设备回执。观察到工作区写入、构建或未知 Shell 变更后，旧 CLI 与 Git 检查不用于当前产物，HTTPS 仍可作为历史实测。Git 根目录相等只依据同一归档的当前目录或 Git 前缀回执，远程列表只交接命令退出码和输出是否为空。

验收负责人按原回执记录 HTTPS 与 CLI 的先后，已有有效 HTTPS 状态时直接引用。测试数量优先取最终 Maven 回执的已核验汇总，汇总缺失时允许读取已有测试报告。

首次桌面验收交接拥有可信上游回执且可保留工单全文时，角色提示复用这些回执和独有成员内容。成员的追加测试变体作为建议，Git、HTTP 和 CLI 结论引用实际设备回执。恢复、重试和缺少上游回执的执行沿用完整提示。

配置了最终验收命令且实际绑定本机 Shell 时，模型提示使用执行器解析后的每轮工具调用上限。Agent 可据此将同一产物上的独立检查成组提交，逐项覆盖工单要求并保留每条设备回执。最终命令仍按原配置单独提交。

最终构建前的 CLI 按原命令合并，验收员的实测覆盖上游同命令结果。已确认仅初始化 Git 元数据时仍可复用上游的构建前 CLI。README 从验收员已核对内容哈希的完整读取回执中提取构建和运行命令。

成员工具绑定齐备时，图状态记录执行顺序中最后一位本机 Shell 成员作为验收负责人。其他成员的写入和 Shell 操作仍会使已有回执失效。验收负责人最多可使用 12 轮，并受父任务轮次上限约束。审批恢复从原 checkpoint 读取负责人。验收负责人查询本租户父任务的当前设备回执，并获得重复读取提示、最后三轮提醒和提前终稿时的一次补验机会。父任务按同一账本判定最终状态。

桌面 Team 的 Leader 汇总优先获得验收负责人的回执摘要，使用现有的交接长度上限。验收摘要包括构建退出码、测试数量、产物路径及实际检查结果。

桌面 Team 缺少有效验收回执且所有成员均遭遇模型通道错误时，父执行仍判失败，并提示模型通道不可用。混合结果继续提示缺少验收回执。

## Team Checkpoint 故障处理与保留（2026-11-21）

Team checkpoint 使用应用的 Spring DataSource，沿用连接池、JDBC 参数及 search_path。应用启动时校验当前 schema，已有 JSONB 载荷的库需要先执行 1.9 迁移。空库首次执行 Team 时按当前 schema 建表，并以 PostgreSQL 事务级 advisory lock 协调并发初始化。保留任务默认每小时检查一次，最多清理 250 个已释放、对应执行已终态且完成与最后快照均超过 30 天的线程。删除线程会级联删除其快照。保留天数配置为 0 可关闭清理。

## Agent 循环收敛与观测（2026-11-21）

单次循环结果通过 endReason 表示结束原因，并通过 degraded 标识基于本地证据拼装的降级输出。业务状态沿用 completed、failed、paused 等，实时事件保留原事件类型和正文。agent_loop_outcome 可按 status、endReason、degraded 聚合，agent_model_dispatch 可按 reasoning、reflection、compaction、convergence、revision 聚合。后者记录逻辑模型请求，供应商实际重试以模型调用日志为准。

无证据的轮次上限直接失败，有证据时进入一次强制收敛。强制收敛仍失败或返回空正文时使用证据生成降级输出。安全阻断或暂停先于追加反思，预算耗尽后停止派发模型请求。相同候选最多反思一次，额外的质量修订共用配置的反思次数限制。影子审核仍默认开启，针对同一候选最多等待一次，默认上限为 350 毫秒。

## 语义数据查询安全边界

数据库语义查询采用“结构化意图 → 服务端计划 → 方言查询”的链路。业务数据库不接受前端任意 SQL；当前兼容接口只允许单条只读语句，并由 `SqlReadOnlyGuard` 使用 JSQLParser AST 检查语句类型、`SELECT INTO` 和行锁。

数据库数据源和凭据始终按租户校验。连接配置只保存 `secretRef`，密文由 AES-GCM 凭据仓库存储，MCP 客户端创建前生成短生命周期内存副本。

Jena/TDB2 只存在于 `semantic.infrastructure.jena`。共享 Dataset 由 `SemanticDatasetManager` 持有，业务读取只能通过不可解包的只读门面访问服务端生成的图白名单。门面拒绝写事务，`close()` 不向下传递，避免调用方关闭共享存储。临时图包含 operationId，同一模型版本的并发校验互不覆盖。

语义模型与版本是独立聚合。聚合自身执行状态转换和 revision 校验，application 只编排当前租户上下文与仓储端口。数据库适配器的查询必须显式带 `tenant_id`；更新必须同时匹配 `tenant_id + id + revision`。数据库组合外键保证版本、映射和活动版本不能跨租户关联。

本体图编辑采用 `OntologyStorePort` 的结构化契约：调用方提供模型和版本标识及三元组，application 从 `SecurityUtil` 取得租户并读取版本聚合，只有 `DRAFT`/`INVALID` 可写；Jena 适配器根据服务端 `SemanticGraphIriFactory` 生成 asserted 图。读取同样先解析租户版本，再以受限 `GraphQuery` 返回分页邻域，默认不返回页外资源边，避免前端拿到未加载节点。

发布由 `SemanticPublishPort` 隔离 Jena 类型。适配器把 asserted 和服务端基线 shapes 写入 operationId 隔离的临时图，执行 SHACL 后仅物化子类、子属性、domain、range、等价类和等价属性规则；每条推导写入前检查配额。HTTP API 不接收租户自定义 shapes，避免第一期开放可执行 SHACL 扩展。checksum 对 asserted、shapes、inferred 三类排序后的 N-Triples 表示计算 SHA-256。application 先用 version revision 进入 `VALIDATING`，校验失败写 `INVALID`；校验成功后在同一数据库事务中发布版本并激活模型，再提交临时 shapes/inferred 图。revision 冲突会丢弃临时图，活动版本不变。

Schema 扫描通过 `SchemaMetadataSessionFactory` 打开租户限定的短生命周期会话。关系型和 ClickHouse 适配器只执行内置只读元数据 SQL，并再次经过 `SqlReadOnlyGuard`；MongoDB 只允许集合、结构、索引三类白名单操作。适配器不会把样例值写入领域对象、快照或 API 响应。

语义查询执行通过 `RoutingSemanticQueryExecutorAdapter` 按服务端签名计划路由 SQL 和 MongoDB。Mongo aggregation 只允许单集合、单 pipeline 和受控阶段，pipeline 在 Jackson JSON 树中绑定参数后才传给租户限定的 MCP Server；限制包括 16 个阶段、64KiB、12 层深度和 `QueryExecutionLimits` 的行数/超时。`$out`、`$merge`、脚本、跨集合扩展和搜索扩展均被阻断。Mongo EXPLAIN 只调用显式 explain 工具，工具不可用时返回计划元数据并跳过真实执行。数据源 `connectionConfig` 可通过 `mongoAggregationToolName`/`mongoExplainToolName` 指定白名单别名；适配器依据 MCP `inputSchema.properties` 协商 collection、pipeline、limit、timeout 参数名，并在 schema 要求时把 pipeline 编码为 JSON 字符串。

语义查询审计使用现有 `sf_audit_log` 表，不再以结构化日志作为唯一载体。`MybatisSemanticQueryAuditAdapter` 写入租户、用户、动作、资源、planHash 和 UTC 时间；detail 仅包含 auditId、sourceId、outcome、rowCount、elapsedMs，不写入 SQL、pipeline、参数、结果行或凭据。审计写入仍是同步 fail-closed，写入失败会让调用方感知失败，后续可替换为可靠事件流而不改领域 Port。

`SchemaIntrospectorPort` 接收纯领域值对象 `SchemaScanScope`，数据库差异留在 infrastructure 策略中。快照先规范化排序再计算 SHA-256 fingerprint；`tenantId + sourceId + fingerprint` 唯一约束和重复键回读共同保证并发幂等。

## 已知限制

- 当前 AST 门禁尚未包含表列白名单、函数白名单和成本估算，后续 QueryPlan 编译阶段补齐；
- 旧数据源中可能存在历史明文凭据，编辑保存时迁移，正式上线前需执行数据盘点；
- 当前已完成 Jena/TDB2 基础设施与语义控制面，SHACL 校验、受限推理和查询模板守卫将在后续切片实现；
- 当前控制面提供 application CRUD，HTTP Controller 与权限码契约由后续接口切片交付；
- Schema 扫描 HTTP 端点与语义目录细粒度权限码由后续接口切片统一补齐；
- 当前 Schema 扫描为同步调用，超大库的异步任务、超时和进度查询在容量测试后增加；
- `SemanticDatasetManager` 当前按单 JVM 单写入者部署，不能让多个 Pod 共享同一 TDB2 目录。
- 图查询当前为受限邻域读取，适配器会将 asserted 图 materialize 到 JVM 后筛选；生产大图需在 Query IR 切片改成服务端 SPARQL 分页和查询超时。
- `maxAssertedTriples`、`maxInferredTriples`、`maxGraphNodes` 是硬配额，超过配额会中止当前 TDB2 写事务。
- SHACL 已在发布链路启用，但 Jena 校验当前没有独立墙钟超时；上线前需结合容量测试增加可中断的执行器隔离。
- 推理采用明确的 RDFS/OWL 等价关系白名单，不是完整 OWL 2 DL，也不执行租户自定义规则。
- Mongo aggregation 的 MCP 工具名称和返回包装由数据源实现决定，目前适配器只识别受控 aggregation/explain 别名和常见 rows/data/documents/content 载荷；未知工具名会拒绝执行。上线前仍需用真实 Mongo MCP Server 做端到端契约验收。
- 查询审计当前复用通用审计表，detail 未单独拆列，审计检索依赖 JSON detail；高吞吐场景需评估按事件流异步投递和失败重放。
- PostgreSQL 元数据与 TDB2 图存储无法组成单一 ACID 事务。节点编辑先通过 revision 锁定数据库版本，再写 TDB2；Jena 写失败会触发数据库事务回滚，但 Jena 成功后数据库提交失败仍可能留下已更新图。Phase 2 需以操作日志和补偿任务收敛该极低概率窗口。

## Agent 执行 Harness（2026-11-25）

- **崩溃恢复。** 根 Solo 在 PostgreSQL 持有可续租的执行所有权。终态条件更新及普通工具领取检查所有者。模型发出的工具调用写入原始轨迹后保存轮次检查点，工具派发前写入调用 ID，收到结果后写回结构化回执。恢复沿用原执行和消息历史，已经确认的回执可补入模型窗口。结果未知、安全控制未完成、审批处理中断需要人工核对。Team 仍按 LangGraph 检查点恢复已暂停的编排。数据库查询包含租户和执行条件，恢复 API 要求执行权限和创建者身份。
- **验收。** 请求提供的结构断言固定在本次执行上，类型检查使用受限 JSON Pointer。Solo 与 Team 根执行检查实际交付文本，和业务终态一起提交 `acceptanceStatus`。无候选输出记为 `unverified`，断言失败记为 `rejected`。验证通过的正常交付为 `accepted`，降级交付为 `partial`。
- **Team 预算。** 根执行首次进入图时写入共享余额和绝对截止时间，人工暂停保留余额和剩余运行时间，恢复时按剩余时间重新设置截止时间。供应商请求派发前按估算输入及输出上限预占，收到用量后结算。结果未知的模型请求保留预占。在 PostgreSQL 行上排序各成员的预占，余额中的 20%、最多 8,192 Token 留给 Leader 和桌面验收负责人。
- **确定性回归。** 公开 PR 用固定模型响应和工具夹具验证运行轨迹。CI 摘要记录被测 Git SHA 与测试夹具 Git 树，报告保存断言结果。使用完整交付环境的迁移资源运行 PostgreSQL 故障注入和 Team 检查点回归。
