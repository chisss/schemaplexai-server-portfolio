# 业务本体服务设计

## 目标

新建结构化本体可脱离 TDB2 完成配置、校验、发布、图浏览和授权的 Agent 读取。平台保留历史本体图及其查询访问。发布版本必须能在 PostgreSQL 事务故障后安全重试。

## 事务和兼容

- 使用租户、模型和版本作为控制面定位号。创建草稿先锁模型再读取新版本号。有源草稿固定不可变 Schema 快照，保存时用当前授权重新定位表与列。
- 保存时锁定版本、核对修订与模型状态，在一个 PostgreSQL 事务写版本 revision 及 JSON/Turtle 草稿。无结构化产物且已有历史图的版本继续通过原图服务维护。
- 发布前用内存 Jena 检查受控 Shapes，物化白名单推理，计算绑定结构内容和源快照的校验和。版本状态、产物冻结和活动指针在同一个 PostgreSQL 事务提交。旧图仍由原 TDB2 适配器校验和发布。
- 按模型版本读取结构化图。Agent 先校验运行范围再读取发布定义，服务端剥离物理映射。仅业务本体查看权限的用户可浏览已发布定义，源库结构、物理映射与原始产物要求数据源查看权限。
- 结构化版本默认发布为业务上下文。选择查询用途时，必须绑定 PostgreSQL 或 MySQL 快照中的同一张表或视图，至少配置一个指标。求和、均值、最小值和最大值使用整数或精确小数，计数使用已支持的标量字段。维度按已映射属性指定，过滤值使用有业务标签的文本等值。PostgreSQL 时间角色指定 IANA 时区及日、周或月粒度。
- 查询用途在校验通过后同时冻结查询口径，记录快照、字段、物理类型和时间语义。兼容性、发布用途和查询口径进入产物校验和。Agent 业务上下文不读取查询口径或过滤值。SHACL 校验不覆盖实际查询结果或企业验收规则。

## 探索查询候选

- 模型提示输入只包含用户问题和获准列的临时编号、列名、归一化类型。模型从当前租户的可用文本模型中选择，执行一次有界、无工具调用。列注释、类型抽样、数据行和连接信息均在模型输入之外。
- 模型输出经严格 JSON 解析和操作白名单检查。候选只允许对获准列执行最多三项聚合、三个维度和三个类型匹配的等值筛选。SQL、对象名、列选择和最终执行条件由服务端依据授权快照编译，模型输出的字面量须在问题中出现。
- 服务端对常见的显式条件、时间范围、排序与日期进行保守检查。模型对口语的匹配仍可能出错，用户需要先核对已生成计划中的字段和条件，再确认执行。模型不可用或候选无法保留显式限制时返回失败或澄清。
- 本体优先，只有明确未命中才可提议探索。探索需同时满足数据集明确启用、当前用户获授权及独立角色权限。历史 RDF 版本保留旧查询路径。发布口径所用字段不会发送至对应混合数据集的探索模型。
- 自动路由通过 Web 和桌面端的流式事件报告 NL2SQL 回退。规划结果保留授权、来源和模型候选的失败原因，桌面查询历史可回看回退进度。
- Redis 回执固定租户、用户、数据集修订、问题、快照及连接更新标记，十分钟失效。确认时重新检查授权、来源和签名，并执行原计划。桌面结果、历史和导出复核探索权限。探索计划响应只提供获准的统计范围及列标签。

## MySQL 查询

发布与探索均限当前数据集授权的单库对象。发布口径解释时复核连接类型、发布摘要、快照指纹、对象和字段。探索要求只读连接及同方言完整快照，混合数据集的已发布口径和本体映射字段继续从探索候选中排除。精确指标以字符传出，再由结果校验按十进制解析。字符等值筛选使用固定 UTF-8 十六进制参数，语句仍经过只读门禁。MySQL 日期窗口和时间分桶等待来源会话时区契约。独立参考对账由 PostgreSQL 路径提供。

## 独立参考比对

- 管理权限沿用 `database:source:manage`。参考配置按租户和数据集保存，每个数据集最多登记一项。登记锁定数据集，核验其启用状态、只读 PostgreSQL 连接、已发布版本及摘要、固定快照、获准的指标与聚合、相异普通视图和精确数值列。数据库运行时核对视图的 `security_invoker`。
- 单指标发布计划可使用至多三个与登记一致的维度和最多 366 天的日期范围。探索、筛选和时间分桶计划跳过对账。候选和参考使用签名计划的同一组半开时间边界。登记内容改动更新绑定标识，成员授权变动通过数据集策略修订使已预览计划失效。
- 数据源管理员审核独立参考的业务口径、依赖视图和行级范围。平台以同源单条只读语句按匹配维度和精确绝对容差比对。参考侧仅返回计数。任一侧超过 200 组时报告未对账，差异结果禁止导出。带维度或时间映射的参考提供明细供源端聚合，旧单值参考仍须返回一行。
