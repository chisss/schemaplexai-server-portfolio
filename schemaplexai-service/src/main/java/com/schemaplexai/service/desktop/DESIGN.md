# Desktop 执行桥设计

## 目标与选择

复用现有 Server Agent 工具循环，保留企业安全、预算和审计平面。设备工具通过独立执行器和内存 Broker 接入；不把 SSE 展示事件当作可执行指令，不在 Desktop 内复制 Agent Runtime。

本期选择单节点有界等待队列，便于先验证真实工具闭环。设备每 5 分钟无轮询即过期；调用等待最长 120 秒，且受 Agent 执行 deadline 限制。队列、设备和参数缓冲均有配额。

## 威胁模型与安全决策

- JWT 中租户、用户共同限定设备登记、轮询、核验、回传及注销；客户端不能通过请求 body 指定执行 owner。
- 调用关联设备、工作区、Agent、execution 与模型 tool call；Broker ID 为独立随机标识，不能把结果回到其他调用。
- 显式 Desktop context 下 `sys.*` 全部路由设备，未支持工具失败，不回退 Server 文件系统。
- 模型只使用相对本机工作区路径。Server 沙箱与安全 PRE/POST 仍执行，Desktop 用户批准不能放宽企业命令白名单。
- Desktop 执行的分页、详情、日志、控制及会话历史/续接都有 owner 边界。Team 子执行继承原用户和设备上下文。
- 工具仅领取一次；重复、过期或取消后的回传被拒绝。设备执行前必须再次核验，防止旧确认框发起已取消操作。
- 停止或设备注销会唤醒等待，不重发未知结果的副作用操作。终态不能通过旧审批恢复。
- 配置了必跑验证命令的桌面任务需要实际设备回执才能进入完成状态。此要求随根执行保存，审批恢复及 Team 子执行沿用启动时的值。只有授权工作区根目录中的完整匹配命令、设备上报成功及整数退出码 0 才产生有效回执。模型文字和命令标准输出不能单独产生回执。后续工作区写入或 Shell 调用会使旧回执失效。
- 桌面注册时可声明精确文本编辑能力。Server 按当前租户、用户和设备读取能力，支持时提供 `oldText` 和 `newText`，旧客户端仍收到完整 `content` 参数。桌面预览计算替换结果，执行前再次核对目标文件内容。
- 桌面设备可声明行范围读取能力。支持时 `sys.read` 可接收从 1 开始、含首尾的 `startLine` 和 `endLine`。两项均省略时仍读取全文。Server 按租户、用户、设备核对能力并校验行号。归档保留片段和参数，压缩摘要注明范围。

## 已知限制

内存队列不持久化；进程重启会丢失等待调用，多节点必须固定路由到同一节点。生产集群需要持久化调用账本、设备租约、结果去重及恢复协议。

执行前核验之后已经开始的本机动作不可回滚；本机 shell 以员工权限运行，路径检查不是 OS 沙箱。较大文件结果由客户端截断，企业敏感数据出端仍需专门策略与审计配置。

Agent 目前按租户与功能权限授权；逐员工、部门的 Agent 资源授权还需独立补齐。

验证命令的结果由已登记桌面设备提供。运行退出码表示配置命令的执行结果。测试数量、产物内容及外部程序对文件的修改需要在交付验收中单独检查。
